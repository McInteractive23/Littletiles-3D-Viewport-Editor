What is this?

LittleTiles is a Minecraft mod that lets you fill a block's space with many small "tile" boxes instead of one plain block — each box gets its own position, size, block/texture, color, and (for sloped or wedge shapes) independently-moved corners. When you copy a selection in-game, LittleTiles serializes it as SNBT (Minecraft's string form of NBT data): one long string with an integer array per box.

This tool is a workbench for that string. Paste a selection in, then edit it two ways: directly in the 3D preview (click boxes to select them, then move, resize, rotate, mirror, copy or delete them), or through the number fields in the side panels. You can also recolor or retexture boxes as a group, tweak corner offsets and face flips, and export the edited selection back to SNBT to paste into the game.

This is an independent fan tool, not part of LittleTiles itself. It reads and writes the same SNBT format the mod uses, reverse-engineered from real exported selections.

Quick start

  1. Copy a selection in-game with LittleTiles, or grab the SNBT/JSON text some other way.
  2. Paste it into the Import Selection box (or use Choose File) and click Import.
  3. Your boxes appear in the 3D Preview and as cards in the Boxes panel. Click a box in the preview to select it (it gets an orange outline and its card opens), or open its card to edit the position, size, block ID, color, or alpha as numbers.
  4. Press G, S or R to bring up the Move, Scale or Rotate gizmo, and drag its handles. Drag a rectangle over several boxes to work on them together.
  5. Use Groups to recolor or retexture several boxes at once.
  6. When you're happy with the result, copy or download the text from Final SNBT Output and paste it back into the game.

Your work is saved in this browser automatically, so closing the tab doesn't lose it. See Gotchas & FAQ.

The SNBT format

A selection looks roughly like this:

{boxes:1,grid:4,min:[I;1,0,1],size:[I;2,2,2],t:{"minecraft:stripped_spruce_wood[axis=y]":[[I;-1],[I;1,0,1,3,2,3,-2147418096,-65538]]},tiles:1}

The parts that matter for editing:

FieldMeaning
gridHow finely the block is subdivided. See Grid, explained.
tOne entry per block/texture ID, each holding that texture's boxes.
[I;-1]A single-number array right before a box is a color header (packed ARGB) — it applies to every box after it until the next color header.
[I;1,0,1,3,2,3,…]A box: minX,minY,minZ,maxX,maxY,maxZ, then optionally an indicator + packed corner/flip data.

The 4th–6th numbers in a box array are absolute max coordinates, not a size added to min. min=(1,0,1), values (3,2,3) → true size is (2,2,2). The tool's sizeX/Y/Z fields show you that already-computed size — you never need to do the subtraction yourself, it's just worth knowing if you're reading raw SNBT by eye.

When a box has corner offsets or flipped faces, the array carries two more things: an indicator (one integer whose bits mark which of the 8 corners are offset, which faces are flipped, and whether any of this data is present at all), and packed integers holding the actual offset numbers, two squeezed into each integer. You don't need to hand-edit this — the Corner Offsets and Flipped Faces controls read and write it for you — but the Result panel shows the raw decoded values if you're curious or debugging.

Grid, explained

grid says how many tile-units make up one in-game block along each axis — it does not rescale any box's position or size numbers. A box's minX, sizeX, and so on mean the same raw units no matter what grid is selected.

What changes with grid is how big one unit is relative to a block:

  • At grid=2, a box with size 2 in every axis is exactly one full 1×1×1 block.
  • At grid=4, a box needs size 4 to fill a block — so a size-2 box is now a quarter of a block's volume, and it takes 8 of them (2×2×2) to fill the space one grid=2 box used to fill.
  • Doubling the grid again (8, 16, 32…) keeps halving each axis the same way — each step is LittleTiles' own "hammer it into smaller pieces" mechanic, one halving per step.

In this tool, grid mainly affects the 3D preview's floor: the grid lines on the floor are spaced to match whatever grid value is selected, so each square you see really is one in-game block. Presets go up to 1024; pick Custom… from the dropdown for anything higher.

Interface walkthrough

Header

🎮 Controls opens a list of the 3D preview's mouse controls and hotkeys. 📖 Guide is this page, and 📝 GitHub links to the project.

Controls

Grid dropdown, six checkboxes for globally flipping a face, a set of X/Y/Z fields for the 8 corner offsets, and the Import Selection box. Whatever you set in Flipped Faces / Corner Offsets applies to the box that is currently open in the Boxes panel. If several boxes are selected, that is the primary one (see Selecting boxes).

Groups

Boxes are grouped automatically — by texture (block ID) and separately by color. Edit a group's block ID or color/alpha once and it applies to every box in that group. The list next to each group shows its boxes; click one to open it. Apply Shape copies the current Corner Offsets and Flipped Faces from the Controls panel onto every box in the group.

Boxes

One card per box: min position, size, block ID, color, alpha. Click a card's header to expand it. Add Box creates a fresh empty one; Open All / Close All are for scanning through a large selection quickly. The card for each selected box is highlighted. Moving, resizing, copying and deleting boxes is done in the 3D preview rather than on the cards — see 3D preview.

Final SNBT Output & Result

Final SNBT Output is the live-rebuilt string, ready to copy or download. Result shows the currently open box's raw indicator/corner data decoded — mostly useful if something looks wrong and you want to see the numbers behind it.

Saved session banner

If you come back to the tool and a previous session was saved in this browser, a banner at the top offers Restore or Discard.

3D preview

Every box renders live as you edit, using its own color and alpha. Corner offsets bend the box the same way LittleTiles' transformable corners do — pull a top corner down to its base height and that side collapses into a slope automatically, no separate "ramp" shape needed.

Selecting boxes

Selected boxes get an orange outline that follows their real shape, so slopes and wedges are outlined correctly. A fainter copy of the outline shows through any box in front. One selected box is the primary one and its card is the one open in the Boxes panel: the box you clicked last, or the highest-numbered box when you select with a rectangle. Everything in the toolbars below works on the whole selection, except the Controls panel, which edits the primary box only.

Transform gizmos (left toolbar)

Click a button, or press its key, to put a gizmo on the selection. Click or press again to turn it off. The gizmo follows the selection as it changes, and turns off when nothing is selected.

GizmoKeyWhat it does
MoveGDrag an arrow to move along an axis. Positions snap to whole units. A multi-box selection moves together.
ScaleSDrag a handle to resize. The box keeps its min corner and grows or shrinks from there, in whole units (never smaller than 1). For several boxes, the whole selection is scaled from its min corner, so boxes that touched still touch.
RotateRDrag a ring to turn in 90° steps around X, Y or Z. A single box turns around its own center; its corner offsets and flipped faces turn with it. Several boxes turn as one group around a whole-number point near the middle of the selection.

Shape presets (second left toolbar)

One-click shapes for every selected box. Flatten clears the corner offsets so the box is a plain cuboid again (flipped faces are kept). Slope North / East / South / West pulls the two top corners on that side down by the box's full height, so the top face becomes a ramp that descends toward that side.

View modes

Three view modes, top-right of the panel:

  • Solid — filled faces only.
  • Solid+Wire — filled faces with edge lines on top, including the diagonal through each face.
  • Wireframe — edges only, no fill. Boxes can still be clicked and selected.

Flipping a face reverses that face's stored triangle winding — the data that actually gets exported and that the game uses for backface culling in-game. This preview renders every face solid regardless, so a flip won't make anything disappear here; it's a change to the exported data, not to what you see.

Common workflows

Recolor everything using one texture

Find the texture in Groups → By texture and use its color picker + alpha field — every box sharing that block ID updates together.

Build a simple wedge

Select a box and click one of the Slope presets in the 3D preview. Or do it by hand: in Corner Offsets, pull two adjacent top corners down by the box's own height (e.g. −2 on a size-2 box) — the top face becomes the ramp and the wall on that side collapses to an edge automatically.

Move or rotate several boxes together

Drag a rectangle around them (or Shift-click each one), press G to move or R to rotate, and drag the gizmo. They keep their positions relative to each other.

Duplicate part of a build

Select the boxes, press Ctrl+C then Ctrl+V, and press G to drag the pasted copies where you want them. Paste always lands exactly on top of the originals.

Make a mirrored copy

Copy and paste the boxes, move the copies to the other side, then use Mirror X (or Y/Z) so each copy's slopes face the opposite way. Mirror reshapes each box but doesn't move it, so position the copies yourself.

Work at a finer grid

Pick a higher Grid value (or Custom… for anything past 1024) before you start placing boxes, so the floor reference in the 3D preview matches the resolution you're actually building at.

Gotchas & FAQ

My imported box looks bigger than expected. Double check you're reading the tool's sizeX/Y/Z fields, not doing max-minus-min by hand on old exported text — see The SNBT format.

I flipped a face and nothing changed in the preview. That's expected — see the note in 3D preview. The flip is still recorded correctly for export.

Does changing Grid move my boxes? No. It only changes the floor's line spacing in the 3D preview and the grid field in the exported header — box coordinates are untouched.

Can I edit raw SNBT by hand and re-import? Yes — Import re-parses whatever's in the text box, including anything you've hand-edited, as long as the structure stays valid.

I pasted a box and nothing seems to have happened. Paste puts the copy exactly on top of the original, so it looks identical. The pasted copy is selected: press G and drag it away.

I rotated a box and it looks the same. A box that's the same size in the two axes you're turning around (a cube, for example) looks identical after a 90° turn. Its corner offsets and flipped faces still turn with it.

My box moved half a unit after rotating. Positions are whole numbers. If a box's two swapped sizes differ by an odd number (say 3 and 2), it can't stay exactly centered, so it lands half a unit toward the negative side on that axis.

The gizmo disappeared. It turns off when you click empty space or otherwise end up with nothing selected. Select a box and press G, S or R again.

A hotkey does nothing. Hotkeys are ignored while the cursor is in a text or number field, and while the Controls dialog is open. Click on the page background or the 3D preview first.

I deleted boxes by accident. Press Ctrl+Z.

Is my work saved if I close the tab? Yes, but only in this browser. The tool saves your boxes a moment after each change. Next time you open it you'll see a banner with Restore and Discard. Download the SNBT if you need a copy that isn't tied to this browser.
