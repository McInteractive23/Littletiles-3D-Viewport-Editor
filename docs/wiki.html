What is this?

LittleTiles is a Minecraft mod that lets you fill a block's space with many small "tile" boxes instead of one plain block — each box gets its own position, size, block/texture, color, and (for sloped or wedge shapes) independently-moved corners. When you copy a selection in-game, LittleTiles serializes it as SNBT (Minecraft's string form of NBT data): one long string with an integer array per box.

This tool is a workbench for that string. Paste a selection in, edit boxes one at a time or as a group (by texture or by color), tweak corner offsets and face flips, watch a live 3D preview of the result, and export the edited selection back to SNBT to paste into the game.

This is an independent fan tool, not part of LittleTiles itself. It reads and writes the same SNBT format the mod uses, reverse-engineered from real exported selections.

Quick start

  1. Copy a selection in-game with LittleTiles, or grab the SNBT/JSON text some other way.
  2. Paste it into the Import Selection box (or use Choose File) and click Import.
  3. Your boxes appear in the Boxes panel and in the 3D Preview. Click a box to open it and edit its position, size, block ID, color, or alpha.
  4. Use Groups to recolor or retexture several boxes at once.
  5. When you're happy with the result, copy or download the text from Final SNBT Output and paste it back into the game.

The SNBT format

A selection looks roughly like this:

{boxes:1,grid:4,min:[I;1,0,1],size:[I;2,2,2],t:{"minecraft:stripped_spruce_wood[axis=y]":[[I;-1],[I;1,0,1,3,2,3,-2147418096,-65538]]},tiles:1}

The parts that matter for editing:

FieldMeaning
gridHow finely the block is subdivided. See Grid, explained.
tOne entry per block/texture ID, each holding that texture's boxes.
[I;-1]A single-number array right before a box is a color header (packed ARGB) — it applies to every box after it until the next color header.
[I;1,0,1,3,2,3,…]A box: minX,minY,minZ,maxX,maxY,maxZ, then optionally an indicator + packed corner/flip data.

The 4th–6th numbers in a box array are absolute max coordinates, not a size added to min. min=(1,0,1), values (3,2,3) → true size is (2,2,2). The tool's sizeX/Y/Z fields show you that already-computed size — you never need to do the subtraction yourself, it's just worth knowing if you're reading raw SNBT by eye.

When a box has corner offsets or flipped faces, the array carries two more things: an indicator (one integer whose bits mark which of the 8 corners are offset, which faces are flipped, and whether any of this data is present at all), and packed integers holding the actual offset numbers, two squeezed into each integer. You don't need to hand-edit this — the Corner Offsets and Flipped Faces controls read and write it for you — but the Result panel shows the raw decoded values if you're curious or debugging.

Grid, explained

grid says how many tile-units make up one in-game block along each axis — it does not rescale any box's position or size numbers. A box's minX, sizeX, and so on mean the same raw units no matter what grid is selected.

What changes with grid is how big one unit is relative to a block:

  • At grid=2, a box with size 2 in every axis is exactly one full 1×1×1 block.
  • At grid=4, a box needs size 4 to fill a block — so a size-2 box is now a quarter of a block's volume, and it takes 8 of them (2×2×2) to fill the space one grid=2 box used to fill.
  • Doubling the grid again (8, 16, 32…) keeps halving each axis the same way — each step is LittleTiles' own "hammer it into smaller pieces" mechanic, one halving per step.

In this tool, grid mainly affects the 3D preview's floor: the grid lines on the floor are spaced to match whatever grid value is selected, so each square you see really is one in-game block. Presets go up to 1024; pick Custom… from the dropdown for anything higher.

Interface walkthrough

Controls

Grid dropdown, six checkboxes for globally flipping a face, a set of X/Y/Z fields for the 8 corner offsets, and the Import Selection box. Whatever you set here in Flipped Faces / Corner Offsets applies to whichever box is currently open in the Boxes panel.

Groups

Boxes are grouped automatically — by texture (block ID) and separately by color. Edit a group's block ID or color/alpha once and it applies to every box in that group; the dropdown next to each group jumps you to a specific box within it.

Boxes

One card per box: min position, size, block ID, color, alpha. Click a card's header to expand it. Add Box creates a fresh empty one; Open All / Close All are for scanning through a large selection quickly.

Final SNBT Output & Result

Final SNBT Output is the live-rebuilt string, ready to copy or download. Result shows the currently open box's raw indicator/corner data decoded — mostly useful if something looks wrong and you want to see the numbers behind it.

3D preview

Every box renders live as you edit, using its own color and alpha. Corner offsets bend the box the same way LittleTiles' transformable corners do — pull a top corner down to its base height and that side collapses into a slope automatically, no separate "ramp" shape needed.

Three view modes, top-right of the panel:

  • Solid — filled faces only.
  • Solid+Wire — filled faces with edge lines on top, including the diagonal through each face.
  • Wireframe — edges only, no fill.

Flipping a face reverses that face's stored triangle winding — the data that actually gets exported and that the game uses for backface culling in-game. This preview renders every face solid regardless, so a flip won't make anything disappear here; it's a change to the exported data, not to what you see.

Common workflows

Recolor everything using one texture

Find the texture in Groups → By texture and use its color picker + alpha field — every box sharing that block ID updates together.

Build a simple wedge

Add a box, then in Corner Offsets pull two adjacent top corners down by the box's own height (e.g. −2 on a size-2 box) — the top face becomes the ramp and the wall on that side collapses to an edge automatically.

Work at a finer grid

Pick a higher Grid value (or Custom… for anything past 1024) before you start placing boxes, so the floor reference in the 3D preview matches the resolution you're actually building at.

Gotchas & FAQ

My imported box looks bigger than expected. Double check you're reading the tool's sizeX/Y/Z fields, not doing max-minus-min by hand on old exported text — see The SNBT format.

I flipped a face and nothing changed in the preview. That's expected — see the note in 3D preview. The flip is still recorded correctly for export.

Does changing Grid move my boxes? No. It only changes the floor's line spacing in the 3D preview and the grid field in the exported header — box coordinates are untouched.

Can I edit raw SNBT by hand and re-import? Yes — Import re-parses whatever's in the text box, including anything you've hand-edited, as long as the structure stays valid.
